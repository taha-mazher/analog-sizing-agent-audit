# Auditing an LLM agent for analog circuit sizing

[AutoSizer](https://arxiv.org/abs/2602.02849) (ICML 2026) is an LLM agent that sizes analog circuits: the LLM reads
the netlist, picks which transistor widths to tune, narrows their ranges and chooses an optimiser for each round,
with ngspice simulating every candidate. It ships with AMS-SizingBench, 24 circuits on the open SKY130 process, and
reports success rates against genetic algorithms, Bayesian optimisation and other LLM agents.

This project reruns that setup independently from the public release
([yuxi120407/AutoSizer](https://github.com/yuxi120407/AutoSizer), commit `1b9b8f6`, 26 May 2026): ground truth for
the benchmark, plain optimisers at equal simulation budgets over many seeds, and the agent itself with a cloud and a
local LLM. Work in progress; a paper is in preparation.

## Findings so far

1. **The benchmark's success check silently drops negative thresholds.** `check_user_specs_met` in
   `utils/feedback_extraction.py` parses each spec with the regex `(\w+)\s*([><=]+)\s*([\d.]+)`, which cannot match a
   minus sign. Specs such as `lpf_passband_gain_db > -5` are skipped without a warning. On the three filter circuits
   the dropped spec is the one no design meets, so the check passes 36 to 54% of random designs whose true pass rate
   is 0%. Across 180 optimiser runs it reports **93 to 95% success where the true rate is 68 to 70%**, and the agent
   itself stops and declares success on filter designs that miss their gain spec.
2. **Two circuits are passed by every design** (5T-OTA, current-mirror OTA: 100% of their full design spaces meet
   the spec), and two more have fewer designs than the 100-simulation budget (inverter 81, resistive amplifier 96).
   Success on these says nothing about a method.
3. **Plain optimisers set a high bar.** Optuna's TPE meets every spec in 70% of runs on the 12 hard circuits at 300
   simulations, Gaussian-process BO 68% and random search 58%.
4. **The agent's prompt shows the LLM an invalid JSON template.** The circuit-analysis prompt builds the per-metric
   "impact" field with `json.dumps(...)[1:-1]`, which strips its braces. A strong model guesses the intent; Qwen3-8B
   copies it literally (the field comes back as text), and in all 6 attempts the agent crashed at its first or second
   step. With the two braces restored, 17 of 18 trials complete.
6. **The agent is good at the circuits it can be graded on, and claims success on the ones it cannot.** With the
   prompt fixed, Qwen3-8B met every spec in all 8 completed trials on the three hard non-filter circuits (iac, nmcnr,
   smc), where plain optimisers at 300 simulations succeed in 40 to 100% of seeds. On the three filters it declared
   success in all 9 trials after 12 to 24 designs, and none of those designs meets the spec.
5. **Maximising the figure of merit picks infeasible designs.** In 13 of 180 runs the optimiser had already found a
   design that meets every spec but reported a higher-FoM one that does not.

All numbers below are in [`results/summary.txt`](results/summary.txt), regenerated by `python summarize.py` from the
CSVs in `results/`.

## Setup

- **Simulator:** AutoSizer's own runner (`ControlledOTAOptimizer.simulate_ota_config`), ngspice 41, the SKY130 models
  bundled with AnalogGym-Opt. About 1 s per simulation.
- **Scoring:** two ways for every design. *True*: every spec in the circuit's `user_specs_metric` is met, using
  AutoSizer's own auto-generated normalised figure of merit for the FoM line. *AutoSizer's check*:
  `check_user_specs_met(..., fom_only_check=False)`, which is what feeds the success rate in its `main.py`.
- **Runnable circuits:** 22 of 24. `bandgap_reference` needs a pnp model file the release does not include, and
  `switched_capacitor` fails in ngspice.

## Results

### 1. Ground truth

Every design was simulated for the 9 circuits with small spaces (81 to 6,561 designs), and 2,000 random designs for
each of the 13 large ones (200 for the voltage-controlled oscillator, at 40 s per simulation). Share of designs that
meet every spec:

| | circuits |
|---|---|
| 100% (trivial) | five_trans_ota, current_mirror_ota |
| space smaller than the budget | inverter (81 designs), resistive_load_amp (96) |
| 10-50% | dfcfc 45.6 |
| 2-10% | telescopic_ota 8.3, azc 7.6, fdgb 7.1, ldo_regulator 6.9, nand_gate 5.7, folded_cascode_ota 2.4, 3_stage_ring_osc 2.1, buffer 2.0 |
| under 2% | smc 1.4, xor_gate 1.1, iac 0.9, diode_load_amp 0.7, nmcnr 0.2 |
| none found | the three filters (lp, hp, bandp), voltage_controlled_osc |

### 2. Optimisers at equal budgets

*Enumerated circuits, replayed from the ground truth* (`bench.py`, 20 seeds, 100 simulations): on 5 of 9 circuits
every method, random search included, meets every spec in all runs. Only diode_load_amp, resistive_load_amp, xor_gate
and buffer separate the methods; TPE is best or within 5 points of the best on all four.

*The 12 hard circuits, live* (`bench_live.py`, 5 seeds, 300 simulations, 180 runs). Share of runs whose best-FoM
design meets the spec:

| Budget | TPE true / AutoSizer check | GP-BO | Random |
|---|---|---|---|
| 50 | 65 / 88% | 58 / 83% | 38 / 63% |
| 100 | 67 / 87% | 60 / 85% | 48 / 73% |
| 300 | **70 / 95%** | **68 / 93%** | **58 / 83%** |

The whole gap comes from the filters: all 45 filter runs pass AutoSizer's check and none meets the real spec.

### 3. The agent

`run_agent.py` runs AutoSizer's released agent unchanged (main.py settings: 3 variables, 3 regeneration cycles,
plateau patience 2) at its released budget of 100 designs and scores its best design both ways.

| LLM | Trials completed | Claims success | Truly meets spec |
|---|---|---|---|
| Gemini 3.5 Flash | 1 of 1 so far (low-pass filter) | 1 | 0 |
| Qwen3-8B, as released | 0 of 2 (6 attempts, all crashed) | 0 | 0 |
| Qwen3-8B, prompt template fixed | 17 of 18 | 17 | 8 |

Per circuit for the fixed-prompt Qwen agent (3 trials each, Ollama on an RTX 4060, 6 to 27 minutes per trial):

| Circuits | Completed | Claims success | Truly meets spec | Designs used |
|---|---|---|---|---|
| lp, hp, bandp filters | 9 of 9 | 9 | 0 | 12 to 24 |
| iac, nmcnr, smc | 8 of 9 | 8 | 8 | 36 to 171 |

On every filter trial, and on Gemini's one low-pass trial (25 designs, 3 LLM calls), the agent stopped early and
declared success on a design that fails the gain spec, because the dropped negative threshold is the only spec those
designs miss. On the other three circuits it succeeded in every completed trial, but in 4 of 8 it overshot its
100-design budget (124 to 171 designs), since the budget is only checked between optimisation rounds. One nmcnr trial
crashed in all 3 attempts (Qwen listed the same variable as both tuned and fixed); 15 crashed attempts across the run
were retried.

## Caveats

- **The model AutoSizer was published with is not available.** Google no longer serves Gemini 2.5 Flash to new API
  keys, so the cloud runs use Gemini 3.5 Flash. Its free tier allows 20 requests per day, which is why only one
  Gemini trial exists so far.
- **The public code may differ from the code behind the paper.** The paper reports 300 samples and TuRBO; the release
  uses 100 designs and contains no TuRBO.
- **Random sampling cannot prove a circuit infeasible.** For the filters, the best of 2,000 random designs is far from
  the spec (passband gain -7.4 / -21.8 / -22.1 dB against -5 / -15 / -10 dB), and no optimiser run found a feasible
  one either, but a feasible design may still exist.
- **Changes made to AutoSizer for these runs** are in [`patches/autosizer_audit.patch`](patches/autosizer_audit.patch):
  an OpenAI-compatible client for local models (Ollama) with JSON mode, REST transport for the Gemini client, and the
  two-brace prompt fix, applied only when `AUDIT_FIX_PROMPT=1`. The Gemini and as-released Qwen runs use the agent
  as published.
- Three trials per circuit is a small sample; the agent results show a pattern, not a rate.
- The as-released Qwen trials ran at a budget of 50; they crash before the budget matters.

## Reproduce

In WSL or Linux, Python 3.10 with ngspice 41, PyYAML, scikit-optimize, Optuna 5, pandas and PyTorch (CPU):

```bash
git clone https://github.com/yuxi120407/AutoSizer third_party/AutoSizer
git -C third_party/AutoSizer checkout 1b9b8f6 && git -C third_party/AutoSizer apply ../../patches/autosizer_audit.patch
git clone https://github.com/Computing-Intelligent-Decision-Team/AnalogGym-Opt third_party/AnalogGym-Opt
# copy AnalogGym-Opt's bundled sky130_pdk to ~/pdk/sky130_pdk (a local disk, not a Windows mount: 17x faster)

python smoke_test.py                          # three circuits through AutoSizer's runner
bash enumerate_all.sh; bash sample_all.sh     # ground truth (hours; resumable, memory-guarded)
python ground_truth.py                        # feasibility table
python bench.py 20 100                        # replayed optimisers on the enumerated circuits
bash run_live.sh                              # live optimisers on the 12 hard circuits (about 12 h on 4 cores)
MODEL=gemini-3.5-flash bash run_agent_all.sh  # the agent; GOOGLE_API_KEY in .env
MODEL=qwen3:8b LOCAL_LLM_URL=http://localhost:11434/v1 AUDIT_FIX_PROMPT=1 bash run_agent_all.sh
python summarize.py                           # every table above
```

## Files

| File | Purpose |
|---|---|
| `enumerate_space.py`, `enumerate_all.sh`, `sample_all.sh` | full enumeration or random sampling of a circuit's design space |
| `ground_truth.py` | the normalised FoM, the true all-spec check and the feasibility table |
| `bench.py` | random, TPE and GP-BO replayed on the enumerated circuits |
| `bench_live.py`, `run_live.sh` | the same optimisers live on the large circuits, scored both ways |
| `run_agent.py`, `run_agent_all.sh` | the AutoSizer agent, any LLM, scored both ways |
| `summarize.py` | all README tables, written to `results/summary.txt` |
| `results/` | enumerations, samples, simulation caches and every run |
